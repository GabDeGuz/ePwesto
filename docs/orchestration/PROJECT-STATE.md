# Project State Contract

Repository documents define durable requirements and decisions; Git records
revisions; CI/QA evidence applies only to an identified commit; future Issues/PRs
may describe bounded work. None overrides a higher authority or human approval.

Chat is context only. A future GitHub Project may show live task state, but it
cannot override repository authority and none is configured today.

Manual lifecycle: `Backlog -> Proposed -> Approved -> Ready -> In Progress -> QA
-> Review -> Ready to Merge -> Done`. `Blocked` names a dependency/decision;
`Changes Required` returns work to its Implementer. No GitHub Project is
configured or claimed.

`Ready to Merge` is never merge authorization; `Done` requires merged and
reconciled work. The Lead reports conflicting state rather than inferring approval.
